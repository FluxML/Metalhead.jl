API reference

Models

create_model and list_models apply to every ported model. The other functions are the interface of image backbones and classifiers; language models have forward_features, forward_head and forward_intermediates too.

Metalhead.create_model — Function
create_model(name; pretrained = false, revision = nothing, subfolder = "", eltype = Float32, kwargs...)

Build a ported model.

name is a Hub repository ("timm/resnet50.a1_in1k", "HuggingFaceTB/SmolLM2-135M"), a bare architecture ("resnet50", "LlamaForCausalLM"; see list_models), or a local directory containing a config.json and model.safetensors.

By default the weights are random and nothing is downloaded, except the config.json of a repository or directory. With pretrained = true they are loaded from the repository (for a bare architecture, from its default validated checkpoint). revision selects a branch, tag or commit of the repository; validated checkpoints default to the commit they were validated at. The remaining keyword arguments are the original library's model arguments, e.g. timm's num_classes, or the fields of a transformers model's config.json, e.g. num_hidden_layers. Changing num_classes of a pretrained model re-initialises its classifier.

A diffusers repository holds a pipeline, described by its model_index.json, whose components are in subfolders: create_model builds the whole pipeline, and with subfolder (e.g. "vae" or "transformer") a single component, which "org/name/vae" also names.

The model is returned in test mode; call Flux.trainmode! before training.

source
Metalhead.list_models — Function
list_models(; pretrained = false, byfamily = false)

Names of the ported architectures, or with pretrained = true the Hub repositories of the checkpoints they were validated against.

By default, returns a Vector{String}, ordered by architecture name. With byfamily = true, returns a Dict{String, Vector{String}} mapping family identifiers to lists in the same order. For timm, the identifiers are its model module names, such as "resnet", "vision_transformer" and "xception_aligned". With pretrained = true, families without validated checkpoints are omitted.

families = list_models(; byfamily = true)
families["xception_aligned"]
list_models(; byfamily = true, pretrained = true)["resnet"]

Metalhead.forward_features — Function
forward_features(model, x)

Run model up to its last feature map, before pooling and classification (timm's forward_features).

This and forward_head, forward_intermediates and feature_info are the interface of image backbones and classifiers, not of every ported model.

source
Metalhead.forward_head — Function
forward_head(model, features; pre_logits = false)

Apply the pooling and classifier of model to the output of forward_features. With pre_logits = true, return the pooled features before the classifier.

source
Metalhead.forward_intermediates — Function
forward_intermediates(model, x; indices = nothing, norm = false, stop_early = false,
                      output_fmt = "NCHW", intermediates_only = false)

Run model and collect the outputs of its stages or blocks, for dense prediction heads (timm's forward_intermediates). The intermediates are those of feature_info.

  • indices: nothing takes all intermediates, an integer k the last k, and a collection the given positions (1-based, unlike timm's).
  • norm: apply the final norm of the model to the intermediates, where timm does.
  • stop_early: skip the stages after the last selected one.
  • output_fmt: "NCHW" returns WHCN feature maps (the Julia layout of PyTorch's NCHW); transformers also accept "NLC", for (C, L, N) tokens.

Returns (features, intermediates), where features is the output of forward_features (truncated with stop_early), or only intermediates with intermediates_only = true. Vision transformers take return_prefix_tokens = true, which returns each intermediate as a (spatial, prefix) tuple, where prefix holds the class and register tokens.

source
Metalhead.feature_info — Function
feature_info(model) -> Vector{NamedTuple}

The intermediates of forward_intermediates, as timm's model.feature_info: for each, its number of channels num_chs, its reduction (stride) relative to the input, and the PyTorch name module_name of the module that outputs it (timm's module).

Processors

create_processor loads the processor of a checkpoint, which turns raw inputs into the inputs of its model and its outputs back into results. Each processor type ports a class of the Python library of its checkpoints, with its settings as fields.

Metalhead.create_processor — Function
create_processor(name; revision = nothing, subfolder = "", kwargs...)

The processor of a checkpoint: it turns raw inputs (images, text) into the inputs of the model, and the model's outputs back into results (text), as the checkpoint's configuration and its Python library do. create_model makes the forward pass match PyTorch; the processor makes the whole path from raw input to result match.

name is a Hub repository, a local directory or a bare architecture, as for create_model, and validated repositories default to the commit they were validated at. A branch is read at the commit of the first file found, so that the files come from one commit; offline or without network, from the cache. The settings are read from the repository's files over the defaults of the Python class, strictly: a setting that the port doesn't implement is an error, and an unknown key a warning. The keyword arguments override them by name, e.g. size = (; height = 512), where a NamedTuple merges into a nested setting; each goes to the one component that has a setting of that name, and a name that no component has is an error.

Returns the most complete processor the repository describes, as transformers' AutoProcessor does: the class that its files or its model type name, such as a processor that combines an image processor and a tokenizer; else its tokenizer; else its image processor, such as the Timm.EvalTransform of every timm checkpoint. Calling a processor returns what the model takes, a NamedTuple (an array for Timm.EvalTransform). Images are arrays of size (width, height, channels), of integers from 0 to 255 or of reals from 0 to 1 (see image_array). The processor classes are ported along with their models, and a class that isn't ported is an error. show prints each setting and where it comes from.

Metalhead ports no tokenizer: the tokenizer of a repository is HuggingFaceTokenizers.jl's Tokenizer of its tokenizer.json, which needs using HuggingFaceTokenizers before create_processor, and whose token ids start at 0, the token indices of the models at 1:

using HuggingFaceTokenizers
model = create_model("HuggingFaceTB/SmolLM2-135M"; pretrained = true)
tok = create_processor("HuggingFaceTB/SmolLM2-135M")
ids = encode(tok, "The capital of France is").ids .+ 1
logits = model(ids)
decode(tok, [argmax(logits[:, end]) - 1])   # " Paris"

Metalhead.Timm.EvalTransform — Type
Timm.EvalTransform(; input_size = (3, 224, 224), interpolation = "bicubic",
                   mean = (0.485, 0.456, 0.406), std = (0.229, 0.224, 0.225),
                   crop_pct = 0.875, crop_mode = "center")

timm's evaluation transform, create_transform(**resolve_data_config(...)): the image processor of every timm checkpoint, which create_processor builds from the pretrained_cfg of its config.json, resolved as timm's resolve_data_config resolves it: a setting that the configuration doesn't have, or that is false in Python ("", [], 0), takes the default above.

Called on one image or a vector of images, it returns the input of the model, not a NamedTuple: a Float32 array of size (W, H, 3, batch), where (3, H, W) is input_size, of the images resized, cropped and normalized, bit for bit as timm transforms them as PIL images. One image gives a batch of one.

model = create_model("timm/convnext_tiny.fb_in1k"; pretrained = true)
transform = create_processor("timm/convnext_tiny.fb_in1k")
logits = model(transform(image))    # transform(image): 224 × 224 × 3 × 1

An image is an array of size (width, height, channels) (torch's (channels, height, width) reversed) of integers from 0 to 255 (an 8-bit image, as UInt8) or of reals from 0 to 1, which are converted to 8 bits as torchvision's ToPILImage converts them (see image_array). Grey images, and the alpha of RGBA, are converted to RGB as Pillow's convert("RGB") does. Each image is

  1. resized with Pillow's filter interpolation ("nearest", "bilinear", "bicubic", "box", "hamming" or "lanczos"): its short side to floor(input_size / crop_pct) with crop_mode = "center", both sides with crop_mode = "squash". (A non-square input_size with "center" resizes with "bilinear", as in timm.) timm's third crop mode, "border", is not supported;
  2. center-cropped to the height and width of input_size (channels, height, width), padded with zeros where it is smaller;
  3. scaled to [0, 1] and normalized with mean and std.

The settings also take the forms that timm's create_transform takes: input_size as (height, width) or an integer, the side of a square; mean and std as one value for all channels; interpolation and crop_mode as symbols; and crop_pct and crop_mode as nothing for their defaults.

create_processor(repo; use_test_size = true) resolves test_input_size and test_crop_pct in place of input_size and crop_pct, where the configuration has them, as resolve_data_config(use_test_size = True) does: many checkpoints are evaluated at a larger size than the one they were trained at. The other keywords of create_processor override the settings, e.g. crop_pct = 1.0. Timm.pretrained_cfg returns the pretrained_cfg as it is.

source

Metalhead.image_array — Function
image_array(image) -> AbstractArray{<:Real, 3}

image as processors take it: an array of size (width, height, channels) (torch's (channels, height, width) reversed) of integers from 0 to 255 (an 8-bit image, such as UInt8) or of reals from 0 to 1. A matrix is a grey image of one channel. With ImageCore, permutedims(rawview(channelview(img)), (3, 2, 1)) is the 8-bit image of the Matrix{RGB{N0f8}} img that FileIO.load returns.

Metalhead.Transformers.Sam3Model — Type
(model::Sam3Model)(pixel_values, input_ids; attention_mask = nothing,
                   input_boxes = nothing, input_boxes_labels = nothing)

Detect and segment the objects of the images pixel_values (width, height, channels, batch) that the text prompts input_ids (seqlen, batch), 1-based token indices padded on the right after the ones of `attentionmask, describe; withinputboxes` (4, numboxes, batch), boxes (cx, cy, w, h) normalized to the image, also those like the boxes labelled 1 in input_boxes_labels (numboxes, batch) and unlike those labelled 0, -10 marking padding (by default, all are positive). The output of [`getvisionfeatures`](@ref Metalhead.Transformers.getvisionfeatures) can replace the images, and that of [`gettextfeatures`](@ref Metalhead.Transformers.gettext_features) the token indices.

Returns a NamedTuple of

  • pred_masks (W, H, num_queries, batch): the mask logits of the queries, at 4 times the resolution of the patch grid;
  • pred_boxes (4, num_queries, batch): their boxes (x1, y1, x2, y2), normalized;
  • pred_logits (num_queries, batch): their classification logits;
  • presence_logits (1, batch): the logit that the prompt describes something in the image, whose sigmoid times that of pred_logits gives the scores of the queries;
  • semantic_seg (W, H, 1, batch): the logits of a semantic segmentation of the prompt.

diffusers

Metalhead.Diffusers.Flux2KleinPipeline — Type
Flux2KleinPipeline

diffusers' text-to-image pipeline of FLUX.2 [klein], built by create_model from a repository such as "black-forest-labs/FLUX.2-klein-4B". Its components are text_encoder, a Qwen3 language model whose hidden states condition the image; transformer, a Flux2Transformer2DModel that predicts the flow of the latents; vae, the AutoencoderKLFlux2 that decodes them; scheduler, the FlowMatchEulerDiscreteScheduler; and tokenizer, the directory of the tokenizer's files, which the HuggingFaceTokenizers.jl extension loads. is_distilled checkpoints (FLUX.2 [klein] 4B, 9B) sample in a few steps without classifier-free guidance; the base ones (FLUX.2 [klein] base 4B, 9B) take about 50 steps and a guidance_scale of 4.

gpu(pipeline) and bf16(pipeline) move and convert every component.

using Metalhead, HuggingFaceTokenizers
pipe = create_model("black-forest-labs/FLUX.2-klein-4B"; pretrained = true, eltype = BFloat16)
image = pipe("A cat holding a sign that says hello world"; num_inference_steps = 4)

Metalhead.Transformers.chunk_gated_delta_rule — Method
chunk_gated_delta_rule(q, k, v, g, beta; chunk_size = 64)

transformers' torch_chunk_gated_delta_rule with use_qk_l2norm_in_kernel = true, for the queries and keys q and k (headkdim, heads, seqlen, batch), the values v (headvdim, heads, seqlen, batch), the log decays g and the rates beta (heads, seqlen, batch). For each head, with q and k normalised and q scaled by `headkdim^-0.5, the stateS` (headvdim, headk_dim) starts at zero and at each token becomes S = exp(g) * S then S += beta * (v - S * k) * kᵀ, and the output is S * q.

As in transformers, the sequence is padded to chunks of chunk_size tokens, computed in parallel but for the state carried from one chunk to the next, in at least Float32. Each chunk solves a unit triangular system, here by inverting its matrix by blocks, which runs on a GPU and is differentiable. The output has the element type of v.

Metalhead.Transformers.moe_experts — Method
moe_experts(gate_up, down, act, x, top_k_index, top_k_weights)

The experts of a sparse mixture of experts, as transformers' MixtralExperts: each token, a column of x (hidden, n), goes through its experts top_k_index (k, n), whose outputs down * (act(gate) .* up) are summed with the weights top_k_weights (k, n). The stacked weights of the experts are torch's gate_up_proj (numexperts, 2 * intermediate, hidden) and `downproj(num_experts, hidden, intermediate), sogateup` has size (hidden, 2 * intermediate, numexperts) and down (intermediate, hidden, num_experts).

The tokens are grouped by expert and padded to the largest group, so that each projection is one batched_mul, and each token gathers back the outputs of its experts. Unlike a scatter, this needs no atomic additions, which are nondeterministic, and slow in BFloat16 on GPUs before sm_90.

Metalhead.Transformers.qwen3_5_image_inputs — Method
qwen3_5_image_inputs(images; patch_size = 16, temporal_patch_size = 2, merge_size = 2,
                     min_pixels = 65536, max_pixels = 16777216,
                     image_mean = (0.5, 0.5, 0.5), image_std = (0.5, 0.5, 0.5))
    -> (pixel_values, grid_thw)

The inputs of a Qwen3.5 vision encoder (qwen3_5_vision_model) for images, as transformers' image processor of Qwen3.5 (Qwen2VLImageProcessorFast) makes them. The defaults are those of the preprocessor_config.json of the Qwen3.5 checkpoints (min_pixels and max_pixels are its size["shortest_edge"] and size["longest_edge"]).

images is one image or a vector of images. An image is an array of size (width, height, channels) (torch's (channels, height, width) reversed) of integers from 0 to 255 (an 8-bit image, as UInt8) or of real numbers from 0 to 1. For an Images.jl image img, that is permutedims(channelview(img), (3, 2, 1)). Each image is

  1. resized with antialiased bicubic interpolation to the smart_resize of its size with factor = patch_size * merge_size (an 8-bit image along its width and then its height, rounded back to integers after each, as torchvision does on the CPU and PIL),
  2. scaled to [0, 1] (8-bit images only) and normalized with image_mean and image_std,
  3. cut into patches of patch_size × patch_size pixels, each repeated temporal_patch_size times (an image is a video of one frame).

Returns pixel_values, a Float32 matrix of size (patch_size^2 * temporal_patch_size * channels, num_patches) whose columns are the patches of the images one after the other, each image ordered by windows of merge_size by merge_size patches, and grid_thw, an integer matrix of size (3, num_images) whose columns are the numbers of patches (1, height ÷ patch_size, width ÷ patch_size) of the images.

An 8-bit image whose size needs no resizing gives the same pixel_values as transformers, and an image of real numbers the same to Float32 precision. A resized 8-bit image may differ by one level of 255 in about 1% of its values, as torchvision computes its weights in fixed-point arithmetic.

Metalhead.@processor — Macro
@processor struct T <: AbstractProcessor ... end
@processor (components...,) struct T <: AbstractProcessor ... end

Base.@kwdef for a processor class, whose constructors make the processor from standardize_settings of its settings, so that a processor made by hand fails as early as a loaded one. components names the fields that hold the processors it combines, each of type Union{Nothing, C} with the default nothing, which create_processor loads as a processor of class C from the same repository; a component that isn't a C is an error. The component tokenizer, of type Any, is the tokenizer of the repository: HuggingFaceTokenizers.jl's Tokenizer of its tokenizer.json, or nothing without HuggingFaceTokenizers or without the file. With components, T(components...; kwargs...) also makes it from them, e.g. T(image_processor, tokenizer; kwargs...).

Metalhead.Timm.pil_resize — Function
pil_resize(img, (width, height), filter = :bicubic; torchvision = false)
    -> Array{UInt8, 3}

img, a (width, height, channels) array of UInt8, resized as Pillow's Image.resize((width, height), filter) resizes an 8-bit image, bit for bit. filter is one of :nearest, :box, :bilinear, :hamming, :bicubic and :lanczos.

With torchvision = true, for :bilinear and :bicubic, it is resized bit for bit as torchvision resizes a uint8 tensor on an x86 CPU, with antialias = True. torch's variant of the algorithm, from Pillow-SIMD, always resizes the width first, and rounds the weights of each pass to as many bits as int16 holds. (For :bilinear without AVX2, and on a GPU, torchvision resizes in floating point instead.)
